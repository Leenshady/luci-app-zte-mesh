# 2026-10-30 工作日志

## GitHub CI 打包 apk：修复 kernel-headers 下载失败
- 报错：`make toolchain/install` → `toolchain/kernel-headers` 下载 `linux-6.18.38.tar.xz` 失败
  `Cannot find appropriate hash command`（hash="x"，URL=`@//kernel/linux/kernel/v6.x`）
- 根因：cnjn/immortalwrt `sr1010-zx279133` 分支的 ZTE target 用外部内核树
  （`KERNEL_PATCHVER=6.18`，`LINUX_VERSION-6.18=.38` → 6.18.38，`LINUX_KERNEL_HASH=x`）
  不设 `CONFIG_EXTERNAL_KERNEL_TREE` 时 kernel-headers 会去下载不存在的内核 tarball
- 修复：CI 新增 clone 外部内核树 `cnjn/linux-mainline-zte-zxslc-sr1010`（build 分支，--recurse-submodules），
  并在 .config 设 `CONFIG_EXTERNAL_KERNEL_TREE` 指向 `linux-6.18.38/`
- 关键证据链：target/linux/zte/Makefile 的 error 只在无 EXTERNAL_KERNEL_TREE 时触发；
  include/kernel.mk 设 EXTERNAL_KERNEL_TREE 后跳过无效 LINUX_SITE；generic/kernel-6.18 定义版本/hash

## 二次修复：CONFIG_EXTERNAL_KERNEL_TREE 无效，改走 dl/ 预置内核包
- 第一次修法（clone 外部树 + 写 CONFIG_EXTERNAL_KERNEL_TREE）经 CI 实测无效：
  该符号不在 Config-kernel.in / Config-build.in / target/Config.in，`make defconfig` 直接丢弃
- 决定性证据（include/download.mk）：
  - `$(DL_DIR)/$(FILE):` 规则无前置依赖 → 文件存在即跳过 recipe，完全不下载、不校验
  - `check_download_integrity` 在 hash 不匹配时会加 `FORCE` 强制重跑 → 必须写真实 SHA256
- 最终方案（走上游标准路径，不依赖外部树分支）：
  1. `git clone --depth 1 -b codex/sr1010-mainline cnjn/linux-mainline-zte-zxslc-sr1010 → linux-6.18.38`
     （父仓库 build 分支只是把同 URL 的该分支当 submodule 钉住，直接浅克隆分支更省）
  2. `tar --exclude=.git -cf - linux-6.18.38 | xz -T0 -3 > openwrt/dl/linux-6.18.38.tar.xz`
     （顶层目录名必须与 LINUX_VERSION 一致；TAR_OPTIONS 是 `-xf -`，无 strip-components）
  3. `sed -i` 把 target/linux/generic/kernel-6.18 里 `LINUX_KERNEL_HASH-6.18.38 = x` 换成真实 SHA256
  4. rm -rf 内核目录回收磁盘；timeout 90→180 分钟，-j1 改 -j$(nproc)

## 三次修复：kmod 依赖触发 target/linux/zte 的 $(error)
- 现象：kernel-headers 已过，libmnl 编译成功，随后顶层 `Error 2`，子 make 无 Error 行
- 真因链：
  - toplevel.mk 的 `%::` → package/Makefile 按 tmp/.packagedeps **连带构建依赖**
    → zte-mesh 的 +ip-full 拉出 libmnl/iproute2，+kmod-veth/+kmod-sched-core 拉出内核模块
  - 构建 kmod 会求值 target/linux/zte/Makefile，其中
    `ifeq ($(DUMP),) ifeq ($(strip $(CONFIG_EXTERNAL_KERNEL_TREE)),) $(error ...)`
  - 而 CONFIG_EXTERNAL_KERNEL_TREE 若在 `make defconfig` **之前**写入，会被 kconfig 重置为默认 ""
  - 空值时 include/kernel-defaults.mk 的 Kernel/Prepare 还会走 `ln -s ""` 的错误分支
- 关键源码事实：
  - host-build.mk：`$(if $(strip $(PKG_SOURCE_URL)),$(call Download,default))`
    → 设了 EXTERNAL_KERNEL_TREE 时 LINUX_SITE 为空 ⇒ 完全不调 Download ⇒ 不下载内核
  - config-6.18 里 `CONFIG_EXTRA_FIRMWARE_DIR="../../immortalwrt/target/linux/zte/zx279133/firmware"`
    ⇒ 布局必须是 <dir>/immortalwrt + <dir>/linux-mainline-zte-zxslc-sr1010/linux-6.18.38
- 最终 CI 布局：sr1010/immortalwrt + sr1010/linux-mainline-zte-zxslc-sr1010/linux-6.18.38
  - 内核树浅克隆 codex/sr1010-mainline 分支（父仓库 build 分支只是 submodule 钉同一 URL）
  - defconfig 之后 sed 删掉旧行再 printf 追加 CONFIG_EXTERNAL_KERNEL_TREE 绝对路径
  - 仍保留 dl/ tarball + 真实 SHA256 作兜底
  - 分三个目标构建（luci-base → zte-mesh → luci-app-zte-mesh），日志落 build.log，失败时打印摘要并上传 artifact
