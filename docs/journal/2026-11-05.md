## 批 18 · 终端数的替身：问、答、采集三段各补一段

第 17 批收尾时 PLAN 第 3 节写着"主机侧没有可做的了，剩下的都卡在上机窗口"。**这句被用户一条追问推翻了**：
组合 ②③ 的「终端数」那一格是空的，而它空着的原因不是"要上机才知道"，是**沙箱里那个原厂 agent 压根没有可答的数据源**——
原厂这一格数字来自无线驱动经 `cspd`，沙箱两样都没有，`ns-run` 建的私有根连 `/sys` 都不挂。
把缺的三段补上（宿主量数、沙箱应答、主控定时问）全是主机可测的，于是有了这一批。

### 先把前提测出来，再决定替身坐在哪

`tools/lab/enroller.c` 加了一个 `--metric`：按原厂 `I5TlvApMetricsQueryInsert` 的写法组一帧 AP Metric Query
（CMDU `0x800b`，TLV `0x93` = 计数 + BSSID 列表），发进沙箱，把回帧的 `0x94` 逐条打出来。读数很干脆——
**agent 收到查询，一声不响**。这一条决定了替身必须自己把答的那一半做出来，不是去修 daemon。
`--metric` 的注释里另留了两条依据：`0x93` 的字段形状（计数 + BSSID 列表）对着 MultiAP 规范 3.6 的 dissector 核过，
以及"查询点名一个这台 agent 不认识的 BSSID 时，原厂回 Error Code 而不是沉默"（`ApMetricsQueryReceive` →
`slave_find_bss` 那条路径的符号名）。**两条都还是推的，没在设备上读过**——正是 H-15 第⑦ 那半要读的，
别在这里写成已验。

三段各自的位置由"数在哪里"决定：

- **采集（A）在宿主**：`openwrt/zte-mesh/files/sta-collect`，procd 实例，5 秒一轮，写 `/run/zte-mesh/ap-sta`
  （一行 `epoch=`，之后每路一行 `BSSID 数`）。三个坑是它的判据：①**AP 名单只取 netifd 里 `mode=ap` 的接口**——
  子节点那条朝主控建的回程 sta 接口自己也有 `stations` 目录，把它数进去就等于"这台子路由有一个终端，就是主控"；
  ②**计数走 debugfs**（`/sys/kernel/debug/ieee80211/phy*/netdev:<if>/stations`），因为 ax3600 那种出厂镜像上
  `iw`、`hostapd_cli`、`wpa_cli` 一个都没有，目录列举不需要包也不需要守护进程在说话；
  ③**整表先写到临时名再 `mv`**——应答的那一侧正在读它，半份文件就是一份半网络。
  `stations` 目录**不存在**时这一路整个不进表：内核没话说≠"0 个终端"，一行 0 会被当成量过的数报回主控。
- **应答（B）在沙箱内**：`src/agent-ap-metrics.c`，编进 `libzte_controller_trace.so`，挂在收帧钩子上。
  空列表＝本机跑的每一路；点名的只回点名的那几路；表超过 30 秒没刷新、或 `epoch` 落在未来 ⇒ **回 0 字节＝不吭声**。
  30 秒是六个采集周期，也是主控给一个 `.sta` 文件的有效期——同一个数在链路上只该有一个新鲜度定义。
  发送用的是**查询到达的那个 socket**，而且绕开 `controller-trace.c` 自己的 `sendto` 包装直接 `dlsym(RTLD_NEXT)`：
  走包装等于替 daemon 伪记一次它没做过的收发，日志会说谎。
- **问（C）在主控**：`ap_metrics_query_build()` 组空列表查询，`controller_ap_metrics_query()` 从 `veth-lab`
  （daemon 真正在用的那个口）发出，源地址取 `br0` 的 AL MAC，**发出即不读应答**——应答按那个 MAC 回到 daemon
  自己的 socket，`controller-trace.c` 照常交给 `controller-peer.c` 落盘。**这是这一批最值得留着的一个形状**：
  原厂子节点（真驱动）与 OpenWrt 子节点（这张表）在主控这一侧是同一条写入路径，主控不需要分两条路读，
  也没有为替身新增第二种状态。服务侧 `ap_metrics_reconcile()` 从拓扑就绪等 15 秒起、每 10 秒问**一个**节点
  （一次调用最多发一条，写 `state.json` 的那一秒循环不能被它拖住），节点离开拓扑就停问，文件自己过期——
  这是"这台的终端数还没人上报"和"这台不在了"的分别。

被否掉的一条：主控替子节点猜数。缺的那一路**不补 0**、整表过期**不答**，宁可为空。

## 批 19 · 给采集一条自己的开关，把"停"做成一个变量

### 先试了 procd 那两把杠杆，读回来的不是"采集停了"

⑥ 要的是"这台没人上报终端数"这一个变量。`ax3600` 上停掉 `sta-collect` 只有 procd 那一条路，实测：
`ubus call service delete '{"name":"zte-mesh","instance":"sta-collect"}'` 停得掉，主控约 45 秒后 `state.json` 里这个节点
`stations` 从 `0` 退回 `-1`、`bss_detail` 零行，**而节点行还在**（人没走，只是不报了）。坏消息在后半：恢复只能
`/etc/init.d/zte-mesh start`，那一下把守护进程也换了 pid（16814 → 22636），子节点从拓扑里掉出去十几秒——
**读回来的是"重启了一次"，不是"采集停了"**。所以这一批先把入口做出来，读数留到 r21 装机再读一次。

### 开关跟着 `trace-all` / `mm-off` / `db-profile` 那一套做

`touch /run/zte-mesh/collect-pause`：脚本不再重写表，**表留着、`epoch=` 不再盖章**，30 秒后应答自己就不回了——
沉默跟原厂 agent 一样，报一个陈旧的数才是编一个测量。`rm -f` 那个文件，下一次 5 秒的循环恢复盖章。
暂停期间退出码仍是 0（不给 procd 造 respawn 循环），`paused` 那道闸让"停了"这句话每个进程只说一次。
路径从表的目录推出来（`PAUSE=$DIR/collect-pause`），所以测试把表写到临时根就自带一份开关文件，不用另设环境变量。
这个文件没有任何页面、UCI 选项或 apk 能设，到不了用户的机器。

### 装机读回：把"采集没跑"和"应答没到"分成两行

`ap_sta_rows=` / `ap_sta_age=` 直接读那张表（表不在就两行 `absent`，`epoch=` 那行没了则 `ap_sta_age=unreadable`），
`peer_files()` 从一次采样改成连读：`peer_reads=` 说这次读了几份快照，`peer_input=` 是 H-13/H-15 真正在问的那件事
——**`.sta` 文件存在，或摘要里有 `stations=`**，两条来源任一成立都算有输入。`peer_reports_stations` 保持原来那个更窄的意思
（结束采样那一份快照），因为装替身的机器可以 `peers_sta=2` 旁边写着 `no`，那是设计不是故障。
包里 shell 文件的 marker 加到第五个：`collect_pause_in_collector`——老脚本装到机器上会老实报 `no`。

### 两条自己撞上的坑
